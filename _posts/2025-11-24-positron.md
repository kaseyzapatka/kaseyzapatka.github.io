# Why I Use Positron IDE for my Data Science and Research Workflows

Over the last year I've made the transition from mainly using [RStudio](https://posit.co/download/rstudio-desktop/) and [Jupyter Notebook](https://jupyter.org) to almost exclusively using [Positron](https://posit.co/products/ide/positron/). Ultimately, you need a workflow that best fits your coding needs, but if you're a researcher or academic with a data science bend, I think this is the way forward for setting up workflows and environments. Here is a list of just a few key reasons why I've switched to Positron for my academic research and data science projects and why it's worth it[^disclaimer1]:

### 1. Unified Environment for R and Python

This is probably the main reason: As a researcher and data scientist, I find myself increasingly switching between R and Python on different projects and sometimes even on the same project. Perhaps I pull data using old Python code or a Python-specific workflow, clean it using [R's tidyverse](https://tidyverse.org), run a machine learning workflow using a specific Python library, and then make my findings interactive using an [R Shiny App](https://shiny.posit.co). Not only can I do this in Positron, but switching back and forth seamlessly is exactly what Positron is designed for, and I find it invaluable. When I want to mix visualizations with my coding (e.g., documents—papers, slides, books, reports), I can simply open a Jupyter Notebook file (.ipynb) or create a Quarto document (.qmd), seamlessly integrating R and Python in the same IDE with native support. You can even switch the language for each individual cell easily if you need. This is perfect for my academic and teaching workflows where I'm constantly mixing analysis, visualization, writing, and reproducibility.

### 2. Multi-Session Consoles

I use this feature constantly and it's a big reason I prefer Positron to RStudio. I can run one console to update my data and another to run a visualization or analysis script simultaneously—even running R in one console and Python in another at the same time. This lets me flip back and forth, optimizing my workflow iteratively as I wait for code to run in one console while working in another, and it helps me keep my coding workflow modular (i.e., data processing/data pipeline in one script and analyses in another). I can also test experimental code in one session without disrupting my main working session or having to restart and lose my environment. Plus, I can compare different parameter settings or model versions side-by-side by running them in separate consoles simultaneously. It's a game-changer for my workflow—no more waiting 20 minutes for long data processing steps to finish before I can work on other parts of my project.

### 3. Modern Performance and Stability

It's noticeably faster and more stable than RStudio. I can handle large file structures without the constant lag I used to deal with on big scripts, and it doesn't crash when I'm working with large spatial data or long-running pipelines. The environment management for both R and Python is way more streamlined, and I love the intuitive debugger, better autocomplete, and improved file navigation. Plus, I can view the same script side-by-side in split panes, so I don't have to constantly scroll up and down when referencing different parts of my code—this is especially helpful when working with long scripts.

### 4. Built on VS Code: Open, Extensible, and Future-Proof

I can customize my workflow with thousands of VS Code-compatible extensions supplied by the open-source extension marketplace Open VSX. I have access to LSP tools, AI assistants, SQL GUI clients, code linters, Docker, and more. For example, in my postdoc I needed to use Secure Shell Protocol (SSH) to access secure eviction data. The Remote-SSH extension has been invaluable in my workflow—I can connect directly to remote servers and run my analysis on high-performance computing clusters without leaving my IDE. All my code editing, debugging, and data exploration happens seamlessly as if I were working locally. It's free, open-source, and designed for research. Whenever you find a nice extension or setting you'd like to add, it's easy to update. One extension I really like is [AIR](https://posit-dev.github.io/air/), which automatically formats your R code. Plus, Posit is clearly investing in Positron as the future over RStudio, so I know I'm not backing a dead horse.

### 5. Excellent Git and GitHub Integration

The diff viewer is so much cleaner than in RStudio, and the side-by-side diff comparison has really improved my commit message writing for git updates. I still use the command line to stage/commit/push, but I know many use the built-in workflow. I think this is really useful when I'm teaching as well—showing students reproducible workflows is pretty straightforward and directly integrated into my workflow through the IDE itself.

### 6. Advanced Data Exploration and Visualization

The dataframe viewer lets me sort values, apply filters, inspect missing values, and perform Excel-like operations straight from the GUI without writing additional code. I can sort and filter rows in the Summary Panel to quickly view summary statistics for specific columns, sorting alphabetically by name or grouping by data type, and filtering by column name to focus on relevant columns during my analysis. The inline plots, dataframes, and visualizations work seamlessly, and I can smoothly switch between script and notebook modes depending on what I need. I find this to be a nice upgrade to RStudio's viewer—less clunky and faster.

### 7. Built-in Reproducible Research Tools

I can render Quarto PDFs, HTML, and slides directly within the IDE without leaving my workspace. Project folder templates let me start new Python or R projects with ready-made templates and environment setup via tools like uv and renv, with easy switching between R and Python environments in my workspace. The project-level settings keep my research workflows clean and portable.

### 8. Context-Aware AI Assistant

Positron Assistant offers data science-specific context by parsing and interacting with the IDE's current state, including the Variables pane (providing names, dimensions, and column names of dataframes), the Plots pane for describing current visualizations, and Python/R database connections. The integrated AI is designed to be transparent, inspectable, and responsible, and can be really helpful to have in addition to all the other things. 

---

If you're still using RStudio or juggling multiple IDEs for different languages, I highly recommend giving Positron a try. It's genuinely changed how I work by smoothing out my workflow and integrating all the skills, programming languages, and tools I use into one place. I definitely see it as the workflow of the future[^disclaimer2]:, and researchers and data scientists who are not using it (or something like it—VS Code) are being left behind.
